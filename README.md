# tradeopsy

**把券商交割单还原成 FIFO 配对账本，用 Odean 1998 口径度量你的处置效应。**

> trade + autopsy。它不判断标的好坏、不做策略回测、不预测未来 ——
> 只做一件事：用你**已经成交**的记录，反推你做决策时的系统性偏差。
>
> 姊妹项目 [ashare-quant](https://github.com/nlim820/ashare-quant) 回答"这个策略赚不赚钱"；
> tradeopsy 回答"**你为什么拿不住**"。

## 如果你只有 30 秒

大多数人打开一份"交易分析"只想确认三件事。这张表直接回答，细节都在下面。

| | |
|---|---|
| **它做什么** | 读你的券商交割单，算一件事：你是不是「赚一点就跑、亏了死扛」。这在行为金融里叫**处置效应**（Disposition Effect），是散户长期跑不赢宽基指数的主因之一 —— 因为它实际会**截断盈利、放大亏损**。 |
| **它不做什么** | 不预测收益、不荐股、不评价未来、不给你排名。只把**已经发生**的交易量化。完整边界见[报告里那一块](#报告里有什么)，以及[明确不做的事](#明确不做的事)。 |
| **凭什么可信** | 221 个测试全绿；FIFO 配对用**人工手算的黄金样本**验证（差 1 分钱就算 bug）；学术基准**全部回原文核实**，据此撤下了两条二手误传；口径可疑处宁可留空，也不给一个"算得出来但算错了"的数。 |

报告第一屏长这样（示例报告 `examples/synthetic_accounts/reports/p01_chase_sell.html`，
合成人格「追涨杀跌」，**已明确标注为合成数据**）：

## 3 分钟：跑起来

不需要真实数据 —— 仓库自带一份合成示例账户（覆盖 10 类真实脏数据：送转、分红、配股、可转债 T+0、拆单……）。

```bash
git clone https://github.com/nlim820/tradeopsy && cd tradeopsy

# 生成单文件 HTML 体检报告（零依赖、不联网、离线可看）
PYTHONPATH=src python -m tradeopsy report examples/sample_account \
    --price-history examples/sample_account_price_history.csv -o report.html

# 或者终端里看文本版
PYTHONPATH=src python -m tradeopsy analyze examples/sample_account \
    --price-history examples/sample_account_price_history.csv

python -m unittest discover -s tests        # 221 个测试
```

想用真实交割单？把它放进 `private/`（**该目录永不进 git**，见[隐私边界](#隐私边界)），然后：

```bash
PYTHONPATH=src python -m tradeopsy report private --price-history private/price_history.csv
```

价格序列从哪来，见[这一节](#价格序列从哪来)。

### 报告里有什么

报告是**分层**的，不同读者可以在不同深度停下：

| 层 | 内容 | 给谁看 |
|---|---|---|
| **第一屏** | 「如果你只有 30 秒」：问题 → 结论 → 三条依据 → 边界 | 只想知道结论的人 |
| **KPI 卡** | 已实现收益 / 胜率 / DE / 持有期 / 交易频率，每张卡都能展开看算法 | 想快速扫一眼全貌 |
| **专业分析** | 两套口径对照、逐日滚动口径、同行基准、累计曲线、持有期分布 | 想判断方法论是否站得住 |
| **自省区块** | 「这个报告不做什么」+「下一步可以做什么」 | 关心结论边界的人 |
| **明细** | 每一笔的建仓/平仓/成本/费用，逐行可回原始流水 | 想审计的人 |

章节标题都做成了「人话主标题 + 专业名副标题」，例如：

> **换个更严的算法，结论还成立吗？**
> <sub>逐日滚动口径 · 每个卖出日重算一次账面端，而不是只看期末</sub>

## 深入：为什么这么设计

### 核心不是报告，是口径

体检报告只是输出形态；真正的工作在报告底下：
FIFO 配对要算对 10 送 3、配股缴款、可转债 T+0，持有期要按 A 股交易日，
PGR/PLR 要给 bootstrap 区间而不是一个孤零零的点，同行基准必须回原文核实
（本项目已据此撤下两条二手误传的基准）。**报告里每个数字都能展开审计回原始流水。**

### ⚠️ 当前状态：Alpha

已经能跑的部分：

- **FIFO 配对引擎**（Decimal 记账，黄金样本测试）
- **CSV 解析层**（编码/表头/列名自动适配；递归扫描子目录；告警带文件名）
- **命令行体检报告**（`tradeopsy analyze`，逐笔已实现 + 按标的归因）
- **处置效应引擎 PGR/PLR**（严格 Odean 1998 口径 + A 股持有期本土化）
- **逐卖出日滚动口径**（Odean 原文精细版：每个卖出日重估账面端，T+1 当日买入不进分母；
  与期末口径并列展示，DE 差额即口径敏感度，需 `--price-history` 逐日价格序列）
- **显著性检验**（计数口径 bootstrap 置信区间 + 双比例 z 检验，小样本自动判"证据不足"）
- **同行基准对照**（Odean 1998 + 武佳薇 2020，全部回原文核实；区间包含检验而非伪分位数，
  文献点落不落进你的置信区间一眼可见；含「核查记录」——两条二手误传基准被撤下的全过程）
- **交易日历**（持有期按 A 股交易日口径，支持行情日期精确日历 / 工作日近似降级）
- **单文件 HTML 体检报告**（`tradeopsy report`，零外部依赖、离线可看、每个数字可展开审计）
- **示例账户数据集**（12 个月 / 两种券商格式 / 含送转配股分红可转债，可复现可测试）
- **十套模拟人格交割单**（examples/synthetic_accounts/：追涨杀跌、反向处置、定投、
  T+0、拆单……每套按行为画像构造，报告结论各不相同；附实测对照表与报告画廊，
  全部标注合成数据）
- **行情取数脚本**（`tools/fetch_prices.py`：从交割单推断标的与区间，腾讯/新浪双源补全日线，
  默认不复权、双源交叉验证零差异；唯一需要 akshare 的地方，核心仍零依赖）
- **纸面账户日更管道**（每个交易日自动撮合、记账、出净值，跑在 GitHub Actions 上；
  账本自 2026-10-30 起累积，目前只有初始行，尚未产出可看的净值曲线）

**221 个测试全绿。**

**持有期口径**：默认按 A 股交易日计算（缺省为工作日近似，误差约 4%）；
想完全精确就给它一份行情 K 线日期（`--calendar`）；`--natural-days` 可退回自然日做对照。
自然日会系统性高估持有期 —— 示例账户上赢家 52.1 自然日 ≈ 37.5 交易日，差 28%。

## 价格序列从哪来

`--price-history` 要的那份「日期,证券代码,收盘价」，券商不提供。仓库带了个脚本帮你拉：

```bash
pip install akshare            # 只有这个脚本需要；tradeopsy 核心仍是零依赖
python tools/fetch_prices.py --from-ledger private/
```

它从交割单里推断标的与日期区间，用腾讯 / 新浪日线补全，输出 `private/price_history.csv`。

**默认不复权，且不建议改。** 账本成本是原始成交价（送转只摊薄每股成本、总成本不变），
前复权会把历史价按除权因子下调 —— 「成本 120 元 vs 前复权价 92 元」凭空多出一笔浮亏，
而这笔浮亏会静默进入 PGR/PLR 的分母。示例账户里五粮液 2026-06-05 有 10 送 3，
不复权下价格与摊薄成本同步跳，两边才对得上。

数据源可信度：腾讯与新浪两源在共同交易日的收盘价**零差异**（实测 600519 / 000001 / 510300）。
东方财富接口在本机实测被限流，不作数据源。标的拉不到的，脚本会逐只列出原因
（未上市 / 已退市 / 区间外无数据），不会静默塞一个假价格进分母。

还没有的：同行基准分位（文献没有个体分布，做不了真分位——已改为区间包含检验）。进度见 [ROADMAP.md](ROADMAP.md)。

## 为什么做这个

市面上已经有很好的交易复盘工具，比如 [HKUDS/Vibe-Trading](https://github.com/HKUDS/Vibe-Trading)（26k★）的 Shadow Account。它把"上传交割单 → 行为画像 → 影子策略回测"做完了。

那为什么还要重做一遍？**因为有三个缺口。**

### 1. 它是 agent 全家桶，不是单点工具

47 个工具、19 个数据源、需要 LLM API key、`pip install` 一大坨依赖。
一个只想看看"我今年炒得怎么样"的人，看到这些就关掉了。

**tradeopsy 的核心引擎零第三方依赖。** 不装 pandas、不装大模型 SDK，也能算完所有交易口径的指标。

### 2. A 股的交割单，比看上去脏得多

通用框架按"买入/卖出"处理，但 A 股交割单里还有：

| 条目 | 幼稚实现的后果 |
|---|---|
| 红股入账、转增 | 股数变多了但成本没摊薄，后续卖出盈亏全错 |
| 股息入账、红利税 | 要么漏算收益，要么错误地冲减成本 |
| 配股缴款 | 当成买入还是分红？处理错就多算或少算一笔成本 |
| 新股入账（打新中签） | 直接丢失，收益凭空蒸发 |
| 担保品划转 | 整批数据抛异常 |
| 可转债 T+0 | 免印花税，按股票费率算会多扣钱 |

**tradeopsy 把这些当成一等公民，而不是异常情况。**

### 3. 大多数工具给你一张表，不给你一句人话

数字堆在那里，用户看完不知道该改什么。

tradeopsy 的最终形态是一份**能发出去的年度体检报告**：一句话结论 + 一张图 + 一个同行对照。
不是"胜率 47%"，而是"**你的处置效应明显，而且这个结论撑得住统计检验**"。

## 三条设计原则

这些原则决定了代码的形状，读代码前先看这三条：

**① 金额一律用 `Decimal`，不用 `float`。**
`0.1 + 0.2 != 0.3` 在金融场景是灾难。舍入用 `ROUND_HALF_UP`（中国财务惯例），不是 Python 默认的银行家舍入。

**② 费用以交割单为准，不重算。**
真实交割单里的佣金、印花税、过户费是券商算好的结果。自己按费率重算，只要费率改过一次（比如 2023-08-28 印花税减半），历史数据就永久性偏差。

**③ 成本以"总成本"为权威，不以"每股成本"为权威。**
10 转 5 之后每股成本是 `10.0051 / 1.5 = 6.6700666…`，保留 4 位再乘回 1500 股会凭空多出 5 分钱。所以账本只维护 `(qty, cost)`，`unit_cost` 纯展示。

## 其他用法

```bash
pip install -e .

# 分析你自己的交割单（文件放 private/，该目录不进 git）
tradeopsy analyze private

# 跑引擎自检（不需要任何真实数据、不联网）
python examples/demo.py

# 纸面账户：回放一段历史，看看它跑起来长什么样
python examples/paper_replay.py --since 2026-05-01

# 纸面账户：真实推进到最新交易日（会写 paper/ 下的账本）
python -m tradeopsy.paper --root .
```

核心引擎零第三方依赖 —— 不装 pandas、不装大模型 SDK。

### 隐私边界

| 目录 | 内容 | 是否进 git |
|---|---|---|
| `paper/` | 纸面账户账本 | ✅ 是（演示资产） |
| `private/` | **真实交割单** | ❌ 永不 |
| `fixtures/` | 手写假数据 | ✅ 是 |

真实交割单含券商账号、持仓规模、交易习惯。一旦进了公开仓库，
GitHub 的提交历史不可撤回 —— 事后删文件也没用。所以 `private/` 是目录级硬隔离，
`git add -A` 也带不走（已验证）。

解析层能自动处理：GBK 编码、表头不在第一行、列名各家不同、
数量带负号、费用拆成多列。认不出的行进【告警】，绝不静默丢弃。

引擎自检输出长这样：

```
标的     建仓日      平仓日          数量         成本       净收入        盈亏  天数
-------------------------------------------------------------------------------------
600519   2026-01-05  2026-09-10       150   168,005.00   257,986.58   89,981.58   248
000001   2026-02-02  2026-04-15     2,000    21,005.53    23,184.44    2,178.91    72
000001   2026-02-09  2026-05-20       500     5,102.63     4,645.98     -456.65   100
```

## 它每天自己在跑

这是本项目最不像"课程作业"的地方：**账户不是一个脚本，是一个每天运行的系统。**

`paper/` 目录下的账本由 GitHub Actions 在每个交易日 15:40（北京时间）自动推进：
取数 → 按目标权重撮合 → 收盘估值 → 写净值 → 生成次日指令 → commit 回仓库。

**commit 历史就是运维日志**，哪一天跑了、哪一天没跑、哪一天数据源挂了，都能逐条核。

### 标的池与策略

6 只 ETF（沪深300 / 中证500 / 创业板 / 科创50 / 证券 / 黄金），双均线轮动：

1. 大盘过滤：沪深300ETF 跌破 MA60 时，不新开仓
2. 趋势过滤：收盘 > MA20 且 MA20 > MA60 → 进入候选
3. 动量排序：按 20 日涨幅取前 2 名，等权
4. 滞回：已持仓的标的只要不跌破 MA60 就继续持有，不因排名滑动而反复换仓

### 2026-05 → 2026-10 回放结果

```
交易日数   121
累计收益   -0.30%        ← 绝对收益几乎是零
最大回撤   -16.18%
基准       沪深300ETF 4.866 → 4.065，-16.46%
超额收益   +16.17%       ← 它真正在证明的东西
成交       20 笔，手续费 0.24%
```

**这不是一个赚钱的策略，这是一个在熊市里保住本金的策略。**
把它写进 README 而不是藏起来，因为 tradeopsy 的立场是：
一份不肯展示亏损的交易记录，不值得做成体检报告。

（回放用 `examples/paper_replay.py` 复现，跑在临时目录，不污染真实账本。）

### 撮合规则不是摆设

每条规则都对应一个真实亏损来源，且都有回归测试盯着：

| 规则 | 不这么做的后果 |
|---|---|
| T 日收盘出信号，**T+1 开盘成交** | 同一个价格既出信号又成交 = 未来函数，收益全假 |
| 一字板（开=高=低）不成交 | 账户会在根本买不进的日子"成功买入"，净值虚高 |
| 佣金最低 5 元 | 小额碎单真实费率是名义费率的 4 倍，年化被吃 1% |
| 差额 < 3% 总资产不调仓 | 每天为对齐权重反复下百元单，手续费磨死 |
| 持仓不在目标里必须清仓 | 不这么写，账户会静默退化成"买入持有"（真实踩过） |

## 正确性怎么验证

没有真实交割单也能验证对不对 —— 用**黄金样本（golden fixture）**。

`tests/test_ledger.py` 里手写了 8 个场景，**每个预期值都是人工按 A 股实际规则手算的**：

| 场景 | 验证什么 |
|---|---|
| 简单买卖 | 费用归属方向（买计入成本、卖扣减收入） |
| 10 转 5 | 送转后总成本分毫不动 |
| 现金分红 | 不冲减成本，单独计入总收益 |
| 三次加仓 + 分批卖 | FIFO 顺序 + 成本/费用分摊守恒 |
| 配股缴款 | 总成本正确增加 |
| 可转债 T+0 | 持有 0 天、免印花税 |
| 部分平仓 | 未平仓部分的成本精确 |
| 卖出超持仓 | 降价到持仓上限并告警，不抛异常 |

判据只有一条：**成本之和必须精确等于买入总成本，费用之和必须精确等于实收费用。** 差 1 分钱就是 bug。

## 明确不做的事

- **不做自动下单。** 纸面账户的每一笔成交都在本地模拟撮合，不连接任何券商交易接口，不产生任何真实委托。它是一份**学习用的模拟账本**，不是程序化交易系统。
- **不预测股价、不给买卖建议、不荐股。**
- **不上传任何数据。** 引擎全部本地运行，交割单不出你的电脑。
- **不在仓库里存真实交割单。** `fixtures/` 里全部是自己编造的假数据。
- **不给分位数排名。** 文献只报群体均值、没有个体分布，硬套一个分布算"你超过 84% 的人"是伪精确。原计划要做，查完原文发现站不住，已撤。

> 本项目是记录与分析工具，不构成投资建议。历史表现不代表未来收益。
